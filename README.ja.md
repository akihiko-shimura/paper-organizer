# paper-organizer

[English](README.md) | 日本語

名前がばらばらな論文 PDF のフォルダを、検索でき、引用に使え、AI エージェントに渡せる蔵書に変えます。
ファイルを何かのソフトに取り込むことはしません。

`paper-organizer` は、各 PDF を Crossref と arXiv に照らして同定し、読める名前に改名し、重複を脇へよけ、
手元に全文検索の索引を作ります。Python のファイル 1 つでできていて、標準ライブラリ以外への依存はありません。
コマンドラインから `papers` として使います。

```
1-s2.0-S0030401899001234-main.pdf   →  1999_Smith_OptCommun_164_1_123.pdf
oe-27-8-11018.pdf                   →  2019_Smith_OptExpress_27_8_11018.pdf
2001.01234v2.pdf                    →  2020_Sato_arXiv_2001.01234.pdf
```

（上の名前は、命名規則 `year_FirstAuthor_Journal_volume_issue_page.pdf` を示すための架空の例です。）

**現状。** 作者が、約 3,200 件の PDF からなる 1 つのコレクションで使っています。今のところ macOS 専用です。
コマンドの出力は今のところ日本語です（[制限と既知の問題](#制限と既知の問題)を参照）。

## なぜ作ったか

何年もかけて増えた論文フォルダは、どこでも似た姿になります。`1-s2.0-S…-main.pdf`、`oe-27-8-11018.pdf`、
`document(3).pdf`。同じ論文が 3 つの名前で 3 回保存されている。テキスト層のないスキャンがある。論文を探すには、
どのフォルダに入れたかを思い出すしかありません。「この論文はもう持っているか」に答えるには、目で探すしかありません。

欲しかったものは 2 つです。

- **人が読めるファイル名。** 手で打つのではなく、出版社自身の記録から作ります。
- **AI エージェントが問い合わせられる索引。** アシスタントが文献紹介の節を下書きするときや、参考文献リストを
  確かめるときに、「DOI X はディスクにあるか、どこにあるか」と尋ねて、推測ではなく正確な答えを得られるようにします。

文献管理ソフトは、ファイルを自分のライブラリに取り込むことで 1 つ目を解決します。このツールは、ファイルを
あなたが作ったフォルダの中の元の場所に置いたままにし、索引は別のプレーンテキストのファイルとして持ちます。

## ほかのツールとの違い

以下の比較は、各プロジェクトの公開ドキュメント（2026 年 10 月時点）に基づきます。現在の状態はリンク先で
確かめてください。

| | 文献管理ソフト（例: [Zotero](https://www.zotero.org/support/retrieve_pdf_metadata)） | 識別子を見つけて改名するツール（例: [pdf2doi](https://github.com/MicheleCotrufo/pdf2doi)、[pdf-renamer](https://github.com/MicheleCotrufo/pdf-renamer)） | レイアウト抽出ツール（例: [GROBID](https://grobid.readthedocs.io/en/latest/Introduction/)） | paper-organizer |
|---|---|---|---|---|
| ファイルの置き場所 | 管理ソフトのライブラリに取り込む | 元の場所のまま | 元の場所のまま | 元の場所のまま（自分で作ったフォルダの中） |
| メタデータの出どころ | 最初の数ページのテキストを、管理ソフトの照会サービスに送る | DOI か arXiv ID を見つけ（メタデータ、ファイル名、テキスト、その次にウェブ検索）、それを解決する | 学習済みのモデルが、ページからヘッダの各項目を読み取る。任意で Crossref と突き合わせて補正する | PDF から識別子か検索クエリを見つける。**値は必ず Crossref か arXiv から取る** |
| その記録がこの PDF のものかの確認 | — | 識別子が存在することを確かめる | — | 返ってきた記録が 1 ページ目のヘッダと一致しなければならない（第一著者に加えて、年・誌名・巻・ページのいずれか）。一致しなければ人手行きにする |
| 動作環境 | デスクトップアプリ | Python パッケージ | Java のサービスまたは Docker | Python のファイル 1 つ、標準ライブラリのみ |
| 何のために作られたか | 執筆と引用 | 改名 | 大規模なテキストマイニング | すでにある山の整理と、エージェントの「持っているか」への回答 |

このツールに固有の点は次のとおりです。

- **測定に基づく理由のある検証（裏取り）。** PDF に印刷された DOI が、その PDF の DOI とは限りません。
  参考文献リストから来たものかもしれませんし、Crossref の記録が同じ表題の別の版かもしれません。この裏取りを
  入れる前は、214 件のうち 5 件または 6 件（2.3〜2.8%）が、何の警告もなく別の論文の名前を付けられていました。
- **正直な「分からない」。** 裏取りに通らなかった記録は `unverified`、一致するものがないファイルは `unresolved` に
  なります。どちらも改名せず、どちらも人が見るための一覧に載せます。作者のコレクションでは、これがファイルの 27% です。
- **何も削除しません。移動はすべて事前に確認できます。** [安全性](#安全性)を参照してください。
- **エージェント向けの形のコマンド**: DOI や arXiv ID での厳密な照会、コンパクトな JSON、BibTeX。そして、
  どの記録なら事実として述べてよいかをエージェントに伝える
  [Claude Code の skill](skills/paper-search/SKILL.md) があります。

ほかのツールのほうが向いている場合:

- ワープロ用の引用プラグイン、注釈の同期、グループライブラリが欲しい場合: 文献管理ソフトを使ってください。
- Windows か Linux を使っている場合（まだ対応していません）。
- ファイルの大半が学位論文、書籍、報告書、英語以外の論文である場合。これらの多くは Crossref にないので、
  「分からない」の山に入ります。

## 仕組み

原則: **同定は照合であって、生成ではありません。** このツールが PDF から取るのは *キー*（DOI、arXiv ID、
検索クエリ）だけです。書誌の値（表題、著者、誌名、巻、ページ、年）はすべて、そのキーが指すレジストリ
（登録データベース）から取ります。項目の値を推定する処理はありません。

```
PDF ──► 1〜2 ページ目の本文(pdftotext。テキスト層が無ければ OCR。ダウンロード時の表紙は読み飛ばす)
     ──► 候補が裏取りに通るまで、段を上から順に試す
           1. 余白にある arXiv の刻印           → arXiv API (プレプリントは独立した記録にする)
           2. PDF の埋め込みメタデータの DOI    → Crossref
           3. 本文に印刷された DOI              → Crossref
           4. 本文かファイル名の arXiv ID       → arXiv API
           5. 最初の 300 文字を検索クエリに     → Crossref。返った表題が本文に文字どおりあり、
                                                  引用の中だけではないときに限って採る
           6. 推測した表題を検索クエリに        → Crossref。正規化した類似度が 0.92 以上のときに限って採る
     ──► 裏取り: 第一著者の姓 かつ (年 または 誌名 または 巻 または 開始ページ) が、
         1 ページ目の最初の 1,500 文字にあること
     ──► 解決済み │ unverified (候補が裏取りに通らない) │ unresolved │ supplement │ error (次に取り直す)
```

この中核のまわりで、次のものが動きます。

| 処理 | 実行されるもの |
|---|---|
| OCR | Apple の Vision フレームワーク。20 行の Swift プログラムから呼びます。PDF のテキストが 200 文字未満のときだけ使います。`swiftc` がなければ `tesseract` に切り替えます |
| 抄録 | `enrich` が、解決済みの DOI を 1 つずつ OpenAlex で引きます |
| 重複 | `dedup` が、解決済みのファイルを DOI でまとめ、最も大きいものを残し、残りを保留フォルダへ移します。出版版も手元にあるプレプリントは、2 つ目の保留フォルダへ移します |
| 改名 | `rename` が、索引から `year_FirstAuthor_Journal_volume_issue_page.pdf` を作ります。改名するのは解決済みの記録だけです |
| 検索 | `index` が、表題・著者・誌名・DOI・抄録・フォルダ名・本文の最初の 3,000 文字を対象に、SQLite FTS5（trigram）のテーブルを作ります |
| 閲覧 | `views` が、誌名・年・分野・第一著者ごとのシンボリックリンクのフォルダを、Finder 用に作ります |
| 再試行 | HTTP 429 と 5xx は、間隔を空けながら再試行します。それでも失敗した照会は、「一致なし」と記録する代わりにファイルを `error` とし、次の実行で取り直します |
| ページの検証（任意） | `vet.py` が、1 ページ目の画像を Claude Haiku に送り、主となる論文の表題を尋ねます。持つのは *拒否権* だけです（下記参照） |

状態はすべて、1 つの JSON Lines ファイル（`papers.jsonl`）にあります。PDF 1 つにつき 1 記録で、どの段で解決したかも
記録します。SQLite のファイルはそこから作るもので、いつでも作り直せます。詳細とフィールドの一覧は
[docs/design.ja.md](docs/design.ja.md) にあります。

## どのくらい正確か

以下はすべて、1 つのコレクションで測ったものです。約 3,200 件の PDF で、大半は光学と物性物理、出版年は
1950 年代から 2026 年まで、大半は英語です。**ほかの分野では結果が変わります**。解決できる割合も、誤りの種類も
変わります。数字には標本の大きさを添えています。小さな標本から出した率は、範囲を限るだけのもので、推定値では
ありません。件数は 2026 年 9 月から 10 月にかけての別々の日に数えたものです。その間に重複を除き、新しいファイルを
足したので、表によって合計が少し違います。

**同定の結果**（n = 3,175 件、2026 年 10 月）:

| 結果 | ファイル数 | 割合 |
|---|---|---|
| 解決済み（改名されるのはこのファイルです） | 2,291 | 72.2% |
| — 本文に印刷された DOI | 1,283 | 40.4% |
| — 最初の 300 文字からの検索クエリ | 548 | 17.3% |
| — 埋め込みメタデータの DOI | 353 | 11.1% |
| — arXiv | 87 | 2.7% |
| — 表題での検索 | 13 | 0.4% |
| — 手入力 | 7 | 0.2% |
| 未検証（候補はあるが、裏取りに通らなかった） | 177 | 5.6% |
| 未解決 | 664 | 20.9% |
| 補足資料（そのままにします） | 43 | 1.4% |

人手行きは 843 件です。未検証と未解決のファイルに、例外的な 2 件を加えた数です。そのうち 617 件は、表題は読めるものの、
自動の問い合わせでは採れる記録が見つからなかったものです。この中身は混ざっています。一部は Crossref に無い文献です
（学位論文、書籍、学会の要旨、報告書、データシート、講義ノート）。一部は、問い合わせが外れただけの普通の論文です。
617 件のうち 146 件は、ページの画像から表題を読めば Crossref の記録が見つかります。多くは、ページの最初の数行が
その論文の書き出しではないためです。また、ファイルの一部はそもそも論文ではありません。そのため 72% は、本物の論文を
どれだけ同定できるかを低めに示しています。どれだけ低いかは、まだ測っていません。

**解決済みのものは正しいのか。** 誤りは解決済みの記録の中に隠れます。そのため、標本はそこから取りました。

| 検査 | 標本 | 結果 |
|---|---|---|
| 段をまたいだ層別無作為標本。1 件ずつ 1 ページ目と目で見比べた | 判定できたもの 38 件 | 誤り 0 件。n = 38 では、誤り率がおおよそ 10% 未満だと分かるだけです |
| 裏取りを入れる前 | 214 | 誤り 5 件または 6 件（2.3〜2.8%） |
| 改名したファイルを 1 ページ目と見比べた | 無作為 20 件 | 20 件の名前が中身と一致 |
| 解決済みの全記録に対する、Claude Haiku でのページの検証 | 約 2,350 | 8 件に印が付きました。調べると、2 件は本当の誤同定、6 件は誤報でした |
| 新しく追加した 50 件に対するページの検証 | 50 | 印が付いたものは 0 件 |

監査では、無作為標本が見逃した種類の誤りも見つかりました。最大のものは、1 ページ目が *前の* 論文の末尾から始まる
PDF です（古いレター誌によくあります）。この場合、ヘッダに他人の参考文献が入ります。こうした事例は 7 件
分かっていて、現在の規則が止めるのはそのうち 6 件です。任意のページの検証があるのは、このためです。

これらの数字が **示していない** こと: ページの検証で印が付かなかった記録の適合率（precision。未測定）と、
ほかの分野や言語のコレクションについての一切です。

**そのほかの測定**

| 対象 | 結果 |
|---|---|
| スキャンしたページの OCR（Apple Vision）を、同じページのテキスト層と比べた | 英語で単語の再現率 91.7%、1 ページあたり 1.3 秒。日本語で文字の再現率 98%（文書 1 件） |
| `enrich` 後に抄録があるファイル | 3,175 件中 2,048 件（65%） |
| 検索: 8 つのテスト用クエリでの、正しい論文の順位 | 全文検索（FTS5）: `1, 4, 2, 1, 1, 1, 4, 1`。表題に対する Apple の文埋め込み: `1, 1, 1, 1, 17, 8, 15, 13` |
| arXiv プレプリントの出版版を、表題と第一著者で探す（Crossref） | 出版版の DOI が分かっている 63 件のうち、59 件がその DOI に一致し、1 件が別の DOI に着きました |

## この設計にした理由と採らなかった案

以下の選択はどれも、同じコレクションで代案を測ったうえで決めました。

| 代案 | 測ったこと | 判断 |
|---|---|---|
| モデル（LLM やレイアウト解析器）に表題・著者・誌名を作らせる | レジストリへの照会は、出版社自身の記録を返します。名前の綴りも含みます。著者名の綴りが誤っていた既存のファイル名は、照会で直りました | PDF から取るのはキーだけ。値は決して生成しません |
| DOI が見つからないとき、LLM に表題を提案させる | 最初の 300 文字を Crossref の書誌クエリに送り、本文に文字どおり現れる表題だけを採ると、LLM の手順が解決していた 20 件のうち 17 件を再現でき、誤りは 0 件でした | LLM の手順は取り除きました |
| Crossref の最上位の結果を、関連度スコアが一定以上なら採る | スコアの値が重なります。正しい結果のスコアは 59、無関係な文字列は 23、誤った論文は 37〜42 でした | スコアは決して使いません。文字列を比べます |
| 表題の類似度だけで採る | 学会の要旨、雑誌論文、後年の書籍の章が、まったく同じ表題を持つことがあります（類似度 1.00） | 裏取りを必須にします |
| 裏取りを厳しくする（巻かページを必須にする） | 解決済み 2,308 件のうち 342 件（14.8%）をはじくことになります。抜き取った 14 件は、ほぼすべて正しいものでした。1 ページ目に巻もページも印刷しない雑誌は多くあります | 採用しません |
| PDF の埋め込みメタデータを値として信用する | 埋め込みの項目は人が手で打ったものです。年の 0 が英字の O になっているものや、書式のそろわない著者名がありました | 埋め込みメタデータは、DOI を見つけるためだけに使います |
| 端末上で動く LLM による OCR | 再現率 45.6%、1 ページあたり 70 秒。4 件中 2 件は、何の通知もなく何も返しませんでした | Apple Vision を直接呼びます |
| 「1 ページ目が別の論文から始まる」ことをテキストの規則で検出する | 規則の組を 3 回続けて作りましたが、どれも新しい事例を見逃しました | 代わりにページを見ます（次の行） |
| 視覚モデルに同定を決めさせる | Claude Haiku は、既知の悪いページ 7 件中 7 件、良いページ 30 件中 30 件で、正しい主表題を読みました（Apple Vision のレイアウトのヒューリスティックでは 7 件中 6 件、30 件中 20 件）。ただし、同じ表題が複数の版に属することがあります | Haiku に与えるのは **拒否権だけ** です。読み取った表題が PDF の中に文字どおりあり、かつ記録と食い違う場合に、その記録を人手行きにします |
| 意味（埋め込み）検索を既定にする | 上の順位を参照してください。8 クエリ中 2 つで優れ、4 つで大きく劣りました。両者のハイブリッドは、8 クエリ中 3 つで全文検索より劣りました | 全文検索を既定にします。埋め込みは任意の機能として残します |
| ファイルを自動で分野別のフォルダに振り分ける | 分野が得られたのはファイルの 56% だけでした。また、既存のフォルダには持ち主自身の分類が入っています | ファイルは元の場所に置いたままにします。代わりにシンボリックリンクのビューを用意します |
| 重複を削除する | — | 決してしません。重複は脇へ移すだけです。削除は持ち主が決めます |

より詳しい説明は [docs/design.ja.md](docs/design.ja.md) にあります。それぞれの安全策が *捕まえない* ものも
書いてあります。

## 使い始める

**必要なもの**

- macOS（macOS 27 で開発しています）
- Python 3.9 以降（インストールするパッケージはありません）
- [poppler](https://poppler.freedesktop.org/)。`pdftotext`、`pdfinfo`、`pdftoppm` のために使います: `brew install poppler`
- 任意: Xcode のコマンドラインツール（`swiftc`）。OCR と、任意の埋め込み検索に使います
- 任意: [uv](https://docs.astral.sh/uv/) と Anthropic の API キー。ページの検証（`vet.py`）にだけ使います

**インストール**

```bash
git clone https://github.com/<owner>/paper-organizer.git
cd paper-organizer
mkdir -p ~/.local/bin
ln -s "$PWD/organize.py" ~/.local/bin/papers     # ~/.local/bin が PATH に入っていること
papers selftest                                   # 通信なしの自己検査。「selftest: ok」と出る
```

**設定**（任意ですが、おすすめします）

```bash
cp config.example.json config.json
```

`mailto` に自分のメールアドレスを設定します。これは連絡先として Crossref と OpenAlex に送られ、あなたの
リクエストは、より安定した「polite」プールで扱われるようになります。`config.json` は git の管理から外してあります。

抄録のためには、OpenAlex の API キー（無料）をおすすめします。`OPENALEX_API_KEY` を設定するか、macOS の
キーチェーンに `openalex-api-key` として保存します。

**最初の実行**

まず、小さなフォルダのコピーで試してください。

```bash
papers add ~/Papers          # フォルダの下の PDF を全部同定し、索引を作る
```

時間がかかるのは最初のスキャンです。1 ファイルあたり数秒なので、3,000 件の PDF でおよそ 2〜4 時間です。
中断して再開できます。応答はキャッシュされます。この時点では、何も移動せず、何も改名しません。`add` は最後に、
`dedup` と `rename` が *行うはずのこと* を表示します。内容に納得できたら、次を実行します。

```bash
papers dedup --apply         # 重複を脇へ移す(削除はしない)
papers rename --apply        # 解決済みのファイルを改名する
papers index && papers views # 検索の索引と Finder 用のビューを作り直す
```

そのあとは、新しい PDF を足すときも `papers add` です。まだ索引にないファイルだけを見ます。

## 使い方

詳しい手引きは [MANUAL.ja.md](MANUAL.ja.md) です。よく使うコマンドは次のとおりです。

| コマンド | すること |
|---|---|
| `papers add [folder]` | 新しい PDF を索引に入れ、予定している重複の移動と改名を表示します。何も動かしません |
| `papers search "fiber laser"` | 全文検索。`AND`、`OR`、`NOT`、`"phrases"`、`title:`、`author:`、`journal:` が使えます |
| `papers has 10.1234/abcd arXiv:2001.01234` | 厳密な答え: この DOI や arXiv ID を持っているか、どこにあるか |
| `papers cite 10.1234/abcd` | BibTeX |
| `papers info` | 索引と論文の置き場の場所、記録の件数、検索の索引が古くなっていないか |
| `papers fix NAME --doi DOI` | 記録を 1 件直します（まず変更内容を表示します。`--apply` で書き込みます） |
| `papers review` → `papers merge` | 未解決のファイルをまとめて埋めます。提案された候補に `y`/`n` で答えます |
| `papers move NAME --to FOLDER` | ファイルの移動と索引の更新を一緒に行います |
| `papers relocate` | 手でファイルを動かしたあとに、索引を修復します |
| `papers views` | Finder 用のシンボリックリンクのフォルダを作り直します |
| `papers undo` | 直前の改名または移動を元に戻します |

`search`、`has`、`info`、`recent` に `--json` を付けると、1 行 1 記録で出力します。

**Claude Code と使う**

```bash
mkdir -p ~/.claude/skills ~/.claude/agents
ln -s "$PWD/skills/paper-search" ~/.claude/skills/paper-search
ln -s "$PWD/agents/paper-librarian.md" ~/.claude/agents/paper-librarian.md
```

- **skill** は、「…の論文は持っているか」「手元の論文から…についての論文を探して」のように尋ねると読み込まれます。
  エージェントに対して、ファイルのパスで答えること、書誌の詳細を事実として述べるのは検証済みの記録に限ること、
  検索中は論文の置き場を決して変更しないことを指示します。
- **司書サブエージェント** は、論文の置き場まわりの雑務（PDF の追加、条件による論文の選択、移動の提案）を、
  自分専用の小さなコンテキストで行います。dry run で止まり、計画を返します。変更を適用するのは、持ち主が
  特定の一覧を承認したと依頼文に書いてあるときだけです。

どちらのファイルも日本語で書かれていて、英語のトリガーフレーズが付いています。Claude は、どちらの言語でも
それに従います。

## 安全性

- **PDF を削除することは決してありません。** 重複は、論文の置き場の中の保留フォルダへ移します。削除するか
  どうかは、あなたが決めます。
- **既定は dry run です。** `dedup`、`rename`、`move`、`relocate`、`fix` は計画を表示するだけで、`--apply` を
  付けるまで何も変更しません。`add` は `--apply` をそもそも受け付けません。
- **書き込みの前にバックアップします。** 索引を書き換えるコマンドは、まず索引を `backups/` へコピーします。
  索引とキャッシュのファイルはアトミックに書き込むので、実行が中断されても前の版がそのまま残ります。
- **元に戻せます。** `rename` と `move` は、触れたファイルをすべて記録します。`papers undo` は直前の実行を
  元に戻します。`dedup` も同じ種類の記録を書きます（元に戻すのは手作業です）。
- **有料の呼び出しには同意が必要です。** `vet.py` は費用の見積もりを表示し、`--apply` がなければ何も送信しません。
- **検査そのものも検査しています。** 安全策にはそれぞれテストがあります。どのテストも、守っているコードを
  わざと壊すと失敗することを確かめてあります。

## マシンの外に出るもの

| 送り先 | 送られるもの | いつ |
|---|---|---|
| Crossref | PDF の中で見つかった DOI。検索クエリとして、PDF のテキストの最初の 300 文字と、推測した表題。設定していれば、連絡先のメールアドレス | `add`, `scan`, `review`, `pubver`, `fix --doi` |
| arXiv | arXiv ID | `add`, `scan` |
| OpenAlex | 解決済みの記録の DOI。設定していれば、API キーと連絡先のメールアドレス | `enrich`（`add` の一部） |
| Anthropic | 検証する各 PDF の 1 ページ目の画像 | `vet.py --apply` を実行したときだけ |

この任意のページ画像を除けば、PDF ファイルがアップロードされることはありません。索引（`papers.jsonl`）は、オフラインで検索できるように、
各 PDF の最初の 3,000 文字と抄録を保存します。**索引を公開しないでください**。著作権のある論文の抜粋を含みます。
そのため、git の管理から外してあります。

## 制限と既知の問題

- **macOS 専用です。** OCR と任意の埋め込みは Apple のフレームワークを使います。キーの保存には macOS の
  キーチェーンを使います。PDF の最初の 3,000 文字より先の検索は、Spotlight に頼ります。
- **コマンドの出力、生成されるフォルダ名、コード中のコメントは日本語です。**
- **1 人、1 台のマシン向けです。** 索引は絶対パスを保存し、リポジトリのフォルダに置かれます。マシン間での
  索引の共有には対応していません。
- **すべてを同定できるわけではありません。** 学位論文、書籍、多くの学会の要旨、英語以外の論文の大半は
  Crossref にありません。日本語（やそのほかの非ラテン文字）の表題は、まったく照合されません。
- **同じ表題で、版が違う場合。** 1 ページ目に誌名も巻もページも印刷されていなければ、会議録の版と雑誌の版を
  区別できません。
- **プレプリント。** 認識するのは arXiv だけです。プレプリントとその出版版は、互いにリンクした 2 つの論文として
  扱います。
- **重複は DOI だけで検出します。** 同じ論文が 2 つの DOI で登録されていると、2 つのファイルのまま残ります。
- **1 つのコレクションで測定しました。** [どのくらい正確か](#どのくらい正確か)を参照してください。

未対処の問題の全一覧は [docs/design.ja.md](docs/design.ja.md) にあります。

## 費用

同定、抄録、検索は、無料の公開 API を使います。有料の機能は、任意のページの検証（`vet.py`、Batch API 経由の
Claude Haiku）だけです。作者のコレクションでは、3,203 件で 3.31 USD、50 件で 0.05 USD でした。
